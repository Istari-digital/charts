{{- if dig "enabled" false (default dict .Values.jaeger) }}
Jaeger APM is enabled.

The Jaeger UI is not exposed outside the cluster. Access it via port-forwarding:

  kubectl port-forward svc/{{ include "istari-platform.jaeger.fullname" . }} -n {{ .Release.Namespace }} 16686:16686

then open http://localhost:16686 in your browser.

In-cluster services export traces via OTLP to {{ include "istari-platform.jaeger.otlpUrl" . }} (gRPC) or {{ include "istari-platform.jaeger.otlpHttpUrl" . }} (HTTP).
{{- end }}
{{- if .Values.apiGateway.enabled }}
{{- $routes := include "api-gateway.routes" . | fromJsonArray }}

The API Gateway is enabled. In-cluster clients reach it at http://{{ include "api-gateway.fullname" . }} (port 80) with these routes:
{{- range $routes }}
  {{ .prefix }} -> {{ .service }}:{{ .port }}
{{- end }}

To verify it from your workstation:

  kubectl port-forward svc/{{ include "api-gateway.fullname" . }} -n {{ .Release.Namespace }} 8080:80

then open http://localhost:8080/healthz — you should see "OK".

To expose the API Gateway to clients, point your external load balancer or existing ingress
controller at the {{ include "api-gateway.fullname" . }} Service on port 80, the same way the
registry service is exposed. TLS terminates there — the API Gateway itself serves plain HTTP.
The chart can also create these for you: see `apiGateway.ingress` and `apiGateway.virtualService`.
{{- end }}
{{- if and .Values.identity.enabled (not .Values.provisioner.enabled) (not .Values.provisioner.external) }}

identity-service is enabled without the provisioner. From 2.0.0 it exits at startup unless these
variables are set, and the chart sets them only when `provisioner.enabled` or
`provisioner.external` is true:

  ISTARI_DIGITAL_IDENTITY_SERVICE_REGISTRY_PUBLIC_KEY_B64
  ISTARI_DIGITAL_IDENTITY_SERVICE_FRONTEND_REDIRECT_URIS
  ISTARI_DIGITAL_IDENTITY_SERVICE_MCP_REDIRECT_URIS

If you already supply them, no action is needed. Otherwise set them in the Secret named by
`identity.secretName` or in a Secret listed in `identity.extraEnvSecrets`.
